# S3-compatible storage

The hub has an S3-compatible object store at `http://HUB/s3`. Apps on the mesh can use boto3, aws-cli, rclone or any AWS SDK with no custom client: point `endpoint_url` at `/s3` and use **path-style** addressing (`http://HUB/s3/BUCKET/KEY`).

- **Buckets belong to a project.** An S3 credential is bound to one project and can only see and touch that project's buckets. Bucket names are global across the hub.
- **Credentials** are project-scoped access key pairs. The secret is stored encrypted with the hub's `secrets.key` (the same key as [project secrets](spec-reference.md#secrets)). Revoking a credential, or removing its user from the project, stops it working immediately.
- **Data** lives on the hub's disk under `{data}/s3/`, apart from the `/files` store. Object keys are never used as file paths: each object version is stored as a randomly named blob, so keys like `../../etc/passwd` are just strings.

## Credentials

```sh
ogm s3 credentials create --save     # prints endpoint, access key, secret (shown once); --save caches it for `ogm s3`
ogm s3 credentials ls                # access keys of the project (never secrets), creator, last use
ogm s3 credentials rm OGMS3XXXXXXXXXXXXXXX
```

Use `--project NAME` to create a credential for another project. The REST API:

| Method | Path | |
|---|---|---|
| `POST` | `/v1/projects/{project}/s3-credentials` | → `{access_key_id, secret_access_key, endpoint, region, project, ...}` (201) |
| `GET` | `/v1/projects/{project}/s3-credentials` | list, without secrets |
| `DELETE` | `/v1/projects/{project}/s3-credentials/{access_key}` | revoke (204) |

Access keys look like `OGMS3` followed by 15 uppercase letters and digits. Secrets are 40 characters. The region can be anything (`us-east-1` is a good default). The hub accepts any region in the signature scope.

## Using it

### ogm CLI

```sh
ogm s3 mb models
ogm s3 cp ./llama.gguf s3://models/llama/     # files over 128 MiB go up as multipart (64 MiB parts)
ogm s3 ls                                      # buckets
ogm s3 ls models/llama/ [-r]                   # keys and folders (PRE)
ogm s3 cp s3://models/llama/llama.gguf .       # or "-" for stdout
ogm s3 presign s3://models/llama/llama.gguf --expires 2h
ogm s3 rm s3://models/llama/llama.gguf
ogm s3 rb models                               # bucket must be empty
```

The CLI signs requests itself with SigV4. It takes credentials from `OGM_S3_ACCESS_KEY` / `OGM_S3_SECRET_KEY` (plus an optional `OGM_S3_ENDPOINT`) or from the file `ogm s3 credentials create --save` writes (`~/.config/ogm/s3.json`; on macOS, `~/Library/Application Support/ogm/s3.json`).

### boto3

```python
import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url="http://HUB:7777/s3",
    aws_access_key_id="OGMS3...",
    aws_secret_access_key="...",
    region_name="us-east-1",
    config=Config(signature_version="s3v4", s3={"addressing_style": "path"}),
)
s3.create_bucket(Bucket="datasets")
s3.upload_file("train.parquet", "datasets", "v1/train.parquet")   # multipart for big files
print(s3.list_objects_v2(Bucket="datasets", Prefix="v1/")["KeyCount"])
url = s3.generate_presigned_url("get_object", Params={"Bucket": "datasets", "Key": "v1/train.parquet"}, ExpiresIn=3600)
```

boto3's default `generate_presigned_url` signature (legacy SigV2 query auth) works too. Setting `signature_version="s3v4"` is still recommended.

### aws-cli

```sh
export AWS_ACCESS_KEY_ID=OGMS3... AWS_SECRET_ACCESS_KEY=... AWS_DEFAULT_REGION=us-east-1
aws --endpoint-url http://HUB:7777/s3 s3 mb s3://datasets
aws --endpoint-url http://HUB:7777/s3 s3 sync ./data s3://datasets/v1/
aws --endpoint-url http://HUB:7777/s3 s3 ls s3://datasets --recursive
aws --endpoint-url http://HUB:7777/s3 s3 presign s3://datasets/v1/a.csv
```

aws-cli v2 can store the endpoint in a profile with `endpoint_url = http://HUB:7777/s3` in `~/.aws/config`.

### rclone

```ini
[ogm]
type = s3
provider = Other
access_key_id = OGMS3...
secret_access_key = ...
endpoint = http://HUB:7777/s3
region = us-east-1
force_path_style = true
```

```sh
rclone copy ./checkpoints ogm:training/run-42
rclone ls ogm:training
```

### Go (aws-sdk-go-v2)

```go
client := s3.New(s3.Options{
    BaseEndpoint: aws.String("http://HUB:7777/s3"),
    Region:       "us-east-1",
    UsePathStyle: true,
    Credentials:  credentials.NewStaticCredentialsProvider(ak, secret, ""),
```

### From containers on the mesh

Store the key pair as [project secrets](spec-reference.md#secrets) and pass it in the environment:

```yaml
env:
  AWS_ACCESS_KEY_ID: "{{secret:S3_KEY}}"
  AWS_SECRET_ACCESS_KEY: "{{secret:S3_SECRET}}"
  AWS_ENDPOINT_URL_S3: "http://HUB:7777/s3"   # honored by recent boto3 / aws-cli / AWS SDKs
```

## Supported operations

| Operation | Request | Notes |
|---|---|---|
| ListBuckets | `GET /s3/` | Only the credential's project |
| CreateBucket | `PUT /s3/{b}` | S3 naming rules (3-63 chars, `a-z0-9.-`). `LocationConstraint` is ignored |
| HeadBucket | `HEAD /s3/{b}` | |
| DeleteBucket | `DELETE /s3/{b}` | Must be empty. Pending multipart uploads are discarded |
| GetBucketLocation | `GET /s3/{b}?location` | Always `us-east-1` (empty constraint) |
| GetBucketVersioning | `GET /s3/{b}?versioning` | Always unversioned |
| GetBucketAcl / GetObjectAcl | `GET ...?acl` | Fixed: project has `FULL_CONTROL`. `PUT ?acl` is accepted and ignored |
| ListObjectsV2 | `GET /s3/{b}?list-type=2` | `prefix`, `delimiter` → `CommonPrefixes`, `max-keys` (≤1000), `continuation-token`, `start-after`, `encoding-type=url` |
| ListObjects (v1) | `GET /s3/{b}` | `prefix`, `delimiter`, `marker`, `max-keys`, `NextMarker` |
| PutObject | `PUT /s3/{b}/{k}` | Up to 5 GiB. `Content-MD5` checked if sent. Stores `Content-Type`, `x-amz-meta-*`, `Cache-Control`, `Content-Disposition`, `Content-Encoding`, `Content-Language`, `Expires` |
| GetObject | `GET /s3/{b}/{k}` | `Range` (incl. multi-range), `If-None-Match`/`If-Match`/`If-Modified-Since`, `response-content-*` overrides |
| HeadObject | `HEAD /s3/{b}/{k}` | |
| DeleteObject | `DELETE /s3/{b}/{k}` | Succeeds for missing keys, as in S3 |
| DeleteObjects | `POST /s3/{b}?delete` | Up to 1000 keys, `Quiet` |
| CopyObject | `PUT` + `x-amz-copy-source` | Within or across buckets of the same project. `x-amz-metadata-directive: COPY\|REPLACE`, `x-amz-copy-source-if-(none-)match` |
| CreateMultipartUpload | `POST /s3/{b}/{k}?uploads` | |
| UploadPart | `PUT ?partNumber=N&uploadId=U` | Parts 1-10000, up to 5 GiB each |
| UploadPartCopy | `PUT ?partNumber&uploadId` + `x-amz-copy-source` | With optional `x-amz-copy-source-range` |
| CompleteMultipartUpload | `POST ?uploadId=U` | Parts in ascending order. All but the last ≥ 5 MiB. ETag is `md5(part md5s)-N` |
| AbortMultipartUpload | `DELETE ?uploadId=U` | |
| ListParts | `GET ?uploadId=U` | `max-parts`, `part-number-marker` |
| ListMultipartUploads | `GET /s3/{b}?uploads` | `prefix`, no pagination (first 1000) |

### Authentication

- **SigV4 header auth** (`Authorization: AWS4-HMAC-SHA256 ...`) with any of these `x-amz-content-sha256` values:
  - a literal hex sha256 (checked as the body streams; a mismatch returns `XAmzContentSHA256Mismatch`)
  - `UNSIGNED-PAYLOAD`
  - `STREAMING-AWS4-HMAC-SHA256-PAYLOAD[-TRAILER]` (aws-chunked, every chunk signature verified)
  - `STREAMING-UNSIGNED-PAYLOAD-TRAILER` (aws-chunked with trailing checksums, as newer SDKs send)
- **SigV4 presigned URLs** (`X-Amz-Algorithm=...`), with a lifetime of up to 7 days.
- **SigV2 presigned URLs** (`?AWSAccessKeyId&Expires&Signature`), boto3's default for `generate_presigned_url`. SigV2 *header* auth is refused: use `signature_version='s3v4'`.
- The allowed clock skew is 15 minutes (`RequestTimeTooSkewed`).

Errors are S3 XML (`<Error><Code>SignatureDoesNotMatch</Code><Message>…</Message><RequestId>…</RequestId></Error>`) with the usual codes: `AccessDenied`, `InvalidAccessKeyId`, `NoSuchBucket`, `NoSuchKey`, `NoSuchUpload`, `BucketAlreadyExists`, `BucketAlreadyOwnedByYou`, `BucketNotEmpty`, `InvalidBucketName`, `BadDigest`, `EntityTooSmall`, `InvalidPart`, `InvalidPartOrder`, `MalformedXML`, `NotImplemented`.

## Limits and differences from AWS S3

- **Path-style only.** Virtual-host style (`bucket.HUB`) isn't routed.
- **No versioning, object lock, lifecycle, bucket policies, CORS, tagging, website hosting, SSE options or storage classes.** These subresources return `NotImplemented`, or the matching `NoSuch…` error for GETs. Everything is `STANDARD`.
- **Access control is per project.** There are no per-bucket or per-key ACLs, and anonymous/public buckets aren't supported. Share individual objects with presigned URLs.
- **Checksums:** `x-amz-checksum-*` headers and trailers are accepted but not verified or returned. Integrity comes from SigV4 payload hashes, chunk signatures, `Content-MD5` and ETags (plain objects: `md5`).
- **Single PUT ≤ 5 GiB. Objects ≤ 5 TiB** (multipart). The hub disk is the only real limit. There are no quotas or credit charges for storage yet.
- **CompleteMultipartUpload concatenates the parts** into one file on the hub. For very large objects this takes as long as a local copy and needs that much free space temporarily.
- **Listing cost:** a delimiter listing scans every key under the prefix, including keys inside folders it groups. That's fine for up to hundreds of thousands of keys per prefix.
- **Single hub:** objects live on the hub's disk, with no replication across nodes. Back up `{data}/s3/` together with `ogm.db` and `secrets.key`. Without `secrets.key`, existing S3 credentials can't be verified and have to be recreated.
